# Исправления после ручного теста

Замечания из ручной проверки этапа 1. Сначала собираем список, чинить будем отдельно.
Статусы: `[ ]` — открыто, `[x]` — исправлено, `[?]` — нужно решение.

## Вход и группы

- [ ] **Поиск группы по названию (D33).** Основной путь вступления — поиск по названию, вступление
  сразу, без заявки; скрывать группу из поиска пока не нужно. Вход по коду — отдельный блок внизу
  экрана («Есть код или ссылка?»). Нужны `GET /groups/search?q=` (публичные поля: название, тип,
  число участников) и экран выбора. Доступ можно будет закрыть позже через `join_policy`.
- [ ] **Debounce на поиск группы по коду.** `useGroupPreview` (`packages/core/src/queries/groups.ts`)
  отправляет `GET /groups/join/{code}` на каждый символ, начиная с четвёртого. Нужна задержка
  ~300–400 мс (общий хук `useDebouncedValue` в core); пока идёт ввод, ошибку «не найдено» не показывать.
- [ ] **404 при вводе названия в поле кода.** С телефона вводили `itsu`, `itsi` → 404: поле принимало
  только случайный код. Закрывается пунктом выше; у владельца добавить заметную кнопку
  «Поделиться кодом/ссылкой».
- [ ] **Нет кнопки «Поделиться кодом».** API отдаёт `join_code` участникам с правом приглашать, но в
  приложении код нигде не показан. Добавить в «Ещё → Группа»: код, «Скопировать», «Поделиться
  ссылкой» (системный share), «Сменить код» (`RotateJoinCode` уже есть).
- [ ] **Скрывать пароль при защите аккаунта.** В «Ещё → Защитить аккаунт» (`apps/mobile/src/app/(app)/more.tsx`)
  поле пароля показывает символы. Нужно `secureTextEntry`, кнопка «показать» и
  `autoComplete="new-password"`. Проверить то же в `login.tsx`.

- [x] **Регистрация на телефоне: сервер отвечает 201, приложение показывает ошибку.** Ошибка
  `onResponse: must return new Response()`: в React Native `fetch` — из Expo, его ответ не проходит
  `instanceof Response` в openapi-fetch, а наш middleware возвращал тот же объект. Теперь middleware
  возвращает ответ только при замене и оборачивает «чужой» ответ повтора в `Response`
  (`packages/api-client/src/index.ts`, тест с чужим классом ответа). В dev ошибки запросов пишутся
  в лог Metro (`apps/mobile/src/lib/query.ts`).
- [ ] **Повторные нажатия «Продолжить» создают новых пользователей.** Каждый 201 — новый аккаунт
  (5 штук за 3 секунды). Нужна идемпотентность регистрации (`client_id`/`Idempotency-Key`,
  сгенерированный при открытии экрана), а кнопка должна блокироваться до ответа. Лишних
  пользователей из dev-БД удалить.

## Лента

- [x] **Чипы быстрых тегов перекрыты поиском на вебе.** Добавлен `flexShrink={0}` (проверить на телефоне). На главном экране строка чипов
  («Мои», «Сохранённое», «Непрочитанное», предметы) сплющена по высоте, поле поиска и плашка
  «Входящих» наезжают на неё. Горизонтальный `ScrollView` (`(app)/index.tsx:72`, `flexGrow={0}`) на
  react-native-web сжимается (`flexShrink: 1` по умолчанию), потому что `FlatList` под ним занимает
  всё место. Нужно `flexShrink={0}` (то же в `SubjectPicker`, `components/materials.tsx`); проверить на
  телефоне.
- [ ] **`React does not recognize the a… prop` в вебе.** Всплывающая ошибка React (2 шт.) рядом с
  чипами — вероятно, `accessibilityRole`/`accessibilityState` у `ChipFrame` уходят в DOM (см. пункт
  про `Chip` ниже). Перейти на `role`/`aria-*` (RN 0.86 поддерживает их на всех платформах).
- [ ] **375 из 378 материалов «ждут разбора».** В тестовой папке (саундтрек, подпапок-предметов нет)
  почти все файлы ушли во «Входящие» — это ожидаемо, но плашка «375 материалов ждут разбора»
  и жёлтые значки на каждой строке делают ленту шумной. Подумать: массовый разбор во «Входящих»
  (выбрать несколько → предмет), значок только для модераторов.

## Google Диск

- [ ] **Выученный синоним не переразбирает соседние файлы.** При разборе во «Входящих» имя папки
  стало синонимом предмета («dragon ball z movie 11 …» → «ф»), но остальные 28 файлов той же папки
  остались «ждут разбора»: классификатор запускается только при изменении файла на Диске. После
  `AddAliases` ставить задачу переразбора `needs_review`-материалов группы (или хотя бы этой папки)
  и показывать «Разобрано ещё N файлов».
- [ ] **Индексируются файлы любых типов.** В ленту попали `.flac` и картинки обложек: у загрузок
  есть allowlist расширений (`UPLOAD_ALLOWED_EXT`), у Диска — нет. Решить: пропускать неподходящие
  типы (`SKIPPED` с причиной) или показывать всё, но с фильтром по типу в ленте.
- [ ] **Синоним — длинное имя папки целиком.** Сохраняется вся строка «dragon ball z movie 11
  ''defeat …'' (m1900)». Для учебных папок («Матан», «Лекции Иванова») это нормально, но стоит
  показывать выученный синоним в тосте и давать удалить его в «Предметах группы».
- [ ] **Папки в индексе навсегда остаются в состоянии `NEW`.** 25 папок тестового диска — `NEW`,
  файлы — `LINKED`. На синхронизацию не влияет, но фильтр `drive/items?state=NEW` в диагностике
  показывает папки как необработанные. Ставить папкам отдельное состояние (или `LINKED`).

- [ ] **Публикация на Диск в «Мой диск» (D34).** Ошибка квоты подтверждена вживую: версия получает
  `FAILED`, файл остаётся в S3. Сделать: OAuth-подключение «публикующего» Google-аккаунта старосты
  (scope `drive.file` или `drive`, refresh-токен в БД под AES-GCM), загрузка от его имени; до этого —
  не ставить `drive:upload`, если у подключения нет общего диска и нет OAuth-аккаунта. Позже —
  несколько подключений Диска на группу.
- [ ] **Старые версии файла с Диска открывают текущее содержимое.** Проверка №4: после замены файла
  на Диске обе версии в приложении показывают новый файл — в режиме LINK версия ссылается на тот же
  `drive_file_id`. Сделать: хранить `headRevisionId` в версии и отдавать старые через
  `revisions.get?alt=media` (Google хранит ревизии ~30 дней / 100 штук, если не `keepForever`); если
  ревизии уже нет — показывать «старая версия недоступна». Полное решение — кеш/импорт в S3 (этап 5).
- [ ] **Список материалов обновляется с задержкой после синхронизации.** Проверка №3: карточка
  показывает новое название сразу, лента — «через время» (кеш ленты свежий 60 с). Когда статус Диска
  переходит из `SYNCING` в `OK`, инвалидировать ленту/«Входящие»; до realtime (этап W2-0) — также
  при возврате приложения на передний план и по pull-to-refresh.
- [ ] **Аудио/видео скачиваются вместо воспроизведения.** Проверка №8: `.flac` открылся во встроенном
  браузере и скачался — `Content-Disposition: inline` ставится только PDF и картинкам
  (`filenames.Inline`), а у браузера нет плеера для flac. Сделать встроенный плеер (expo-audio /
  expo-video) по `stream_url` с Range; `inline` для `audio/*`, `video/*`, `text/plain`.
- [x] **Кириллица искажается на телефоне.** В ленте и в карточке материала названия, предметы и
  прочие данные превращались в «ÐÑÐ¸…». Причина — обёртка ответа при повторе после 401
  (`asResponse` в `packages/api-client`): тело передавалось как `ArrayBuffer`, а полифил `Response`
  в React Native (whatwg-fetch) декодирует его побайтно (Latin-1). Проявлялось после первого
  обновления access-токена, искажённые данные сохранялись в кеш. Теперь тело передаётся текстом,
  тест воспроизводит поведение полифила; сохранённый кеш сбрасывается (`QUERY_CACHE_BUSTER`).
- [ ] **Нажатие срабатывает не с первого раза (телефон).** Ощущение при проверке. Вероятная причина:
  пока открыта клавиатура (поле поиска), первое касание списка только закрывает её —
  `FlatList`/`ScrollView` по умолчанию `keyboardShouldPersistTaps="never"`. Поставить `"handled"` на
  экранах с полями ввода; проверить задержку нажатий у `ListRow` на Android.
- [ ] **Неверная ошибка при выключенном Drive API.** Папка не подключилась, потому что в облачном проекте
  не включён Google Drive API: Google ответил `403 accessNotConfigured` / `SERVICE_DISABLED`.
  Но `mapErr` (`apps/api/internal/adapters/gdrive/client.go`) отнёс ответ к «нет прав», и `Connect`
  показал «папка не открыта для сервисного аккаунта». Это вводит в заблуждение.
  Нужно:
  - распознавать `accessNotConfigured` / `SERVICE_DISABLED` и отвечать 503 с текстом «на сервере не
    включён Google Drive API» (плюс ссылка из ответа Google в лог);
  - проверять доступ к Диску при старте `api`/`worker` (`about.get`) и писать понятное
    предупреждение в лог, чтобы ошибка была видна до первого подключения;
  - в `docs/GOOGLE-DRIVE.md` дописать это в «Диагностику».
- [ ] **Тексты ошибок Диска в приложении.** Сервер отдаёт текст ошибки валидации на английском
  («the folder is not shared with …»). Экран Диска должен показывать переведённое сообщение по коду
  ошибки (добавить машинные коды: `folder_not_shared`, `not_a_folder`, `folder_trashed`,
  `drive_api_disabled`) и адрес сервисного аккаунта с кнопкой «скопировать».

## Разработка

- [ ] **Телефон (Expo Go) не может зайти.** Если `EXPO_PUBLIC_API_URL` не задан, `apps/mobile/src/lib/api.ts`
  ходит на `http://localhost:8000`, а на телефоне `localhost` — это сам телефон. Нужно в dev брать хост
  из `Constants.expoConfig.hostUri` (тот же IP, что в `exp://192.168.0.104:4173`) и порт API, а в вебе —
  из `window.location.hostname`. Переменная env остаётся главной.
- [ ] **CORS для веба, открытого по IP.** С `http://192.168.0.104:4173` запросы блокируются: в dev
  разрешён только `localhost:*`/`127.0.0.1:*`. Добавить в dev адреса локальных сетей
  (`192.168.*`, `10.*`, `172.16–31.*`) на любом порту (через `AllowOriginFunc`).
- [ ] **Подтверждения (`Alert.alert`) не работают в вебе.** В react-native-web `Alert.alert` ничего не
  делает, поэтому в браузере кнопки с подтверждением («Отключить Диск» и др.) молча не срабатывают.
  Сделать общий `confirm()` в `packages/ui` (native — Alert, web — диалог Tamagui).
- [ ] **Адрес API и ошибка сети не видны в приложении.** Если приложение не достучалось до API,
  пользователь не понимает почему. В dev показывать на первом экране текущий `API_URL`, а при
  сетевой ошибке писать «Сервер недоступен: <адрес>» (сейчас сетевые ошибки не отличаются от прочих).
- [ ] **Предупреждение `Received true for a non-boolean attribute selectable` в вебе.**
  `<Paragraph selectable>` в `drive.tsx:136` и `material/[id].tsx:178`: на вебе Tamagui передаёт проп
  в DOM. Использовать `userSelect="text"` (веб) или обёртку, которая ставит `selectable` только на native.
- [ ] **`GET /quick-tags` → `net::ERR_FAILED` в вебе.** Разово во время теста Диска. Скорее всего,
  в этот момент API перезапускался. Проверить, повторяется ли; если да — смотреть логи API.
- [ ] **Ошибка рендера `Chip` в вебе.** Metro пишет `Web ERROR` со ссылкой на
  `packages/ui/src/components/chip.tsx:40` (`<ChipFrame … accessibilityState={{ selected }}>`) при
  рендере чипов ленты (`(app)/index.tsx:75`). Текст ошибки в лог Metro не попал — взять из консоли
  браузера. Подозрение: `accessibilityState`/`selected` уходят в DOM на вебе.
- [x] **Файлы на телефоне в dev.** Ссылки собирались с `localhost`: S3 — из `S3_PUBLIC_ENDPOINT`,
  файлы Диска (через API) — из `APP_BASE_URL` (по умолчанию `localhost:8000`). MinIO теперь можно
  открыть в сеть (`MINIO_BIND` в `infra/compose/.env`), настройка для телефона описана в README.
  Осталось на потом: в dev выводить адреса из IP автоматически.

- [ ] **Интеграционные тесты пишут в dev-базу.** В dev-БД остались группы «Материалы …» и «Smoke group»
  от тестов, и они смешиваются с ручными данными. Завести отдельную базу `heatseeker_test`
  (создаётся init-скриптом compose), указать её в `TEST_DATABASE_URL` в `.env.example`, а
  `task api:test:integration` запускать только с ней.
