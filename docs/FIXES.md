# Исправления после ручного теста

Замечания из ручной проверки (этап 1, затем этап 2). Сначала собираем список, чинить будем отдельно.
Статусы: `[ ]` — открыто, `[x]` — исправлено, `[?]` — нужно решение.

## Вход и группы

- [x] **Поиск группы по названию (D33).** `GET /groups/search?q=` (открытые группы, без учёта регистра,
  пустой запрос — все открытые, до 20) и `POST /groups/{id}/join` (вступление сразу, повтор идемпотентен,
  закрытые группы — 403). Экран групп: мои группы → поиск → создание → «Есть код приглашения?» внизу.
  Сценарий в интеграционном тесте.
- [x] **Debounce на поиск группы по коду.** Общий `useDebouncedValue` (core); запросы кода и поиска
  уходят после паузы 350 мс, «Код не подошёл» — только когда ввод закончен. На входе неизвестный код
  не блокирует регистрацию.
- [x] **404 при вводе названия в поле кода.** Закрыто поиском по названию и подсказкой «код — не
  название группы».
- [x] **Нет кнопки «Поделиться кодом».** «Ещё → Пригласить в группу»: код, «Скопировать»
  (expo-clipboard), «Поделиться» (системный share, текст с названием и кодом), «Сменить код» (с правом
  `group.settings`, с подтверждением). Ссылка-приглашение появится вместе с вебом/APK.
- [x] **Скрывать пароль при защите аккаунта.** В Tamagui 2 `secureTextEntry` действует только на
  native, в вебе нужен `type="password"`. `Field` получил режим `password` (оба свойства, автозаполнение,
  кнопка «Показать/Скрыть»); применён на «Защитить аккаунт» и «Вход».

- [x] **Регистрация на телефоне: сервер отвечает 201, приложение показывает ошибку.** Ошибка
  `onResponse: must return new Response()`: в React Native `fetch` — из Expo, его ответ не проходит
  `instanceof Response` в openapi-fetch, а наш middleware возвращал тот же объект. Теперь middleware
  возвращает ответ только при замене и оборачивает «чужой» ответ повтора в `Response`
  (`packages/api-client/src/index.ts`, тест с чужим классом ответа). В dev ошибки запросов пишутся
  в лог Metro (`apps/mobile/src/lib/query.ts`).
- [x] **Повторные нажатия «Продолжить» создают новых пользователей.** Экран регистрации создаёт
  `client_id` (expo-crypto) и шлёт его в `POST /auth/register`; сервер хранит его в
  `users.register_client_id` (миграция 00003). Повтор в течение 15 минут (двойное нажатие, потерянный
  ответ, одновременные запросы) выдаёт новую сессию того же аккаунта и вступает по коду, если он
  передан; после защиты аккаунта `client_id` больше не работает (409). Кнопка заблокирована до ответа.
  Тест `TestRegisterIdempotent`. Лишние пользователи из dev-БД удалены ранее.

## Материалы

## Google Диск

- [x] **Выученный синоним не переразбирает соседние файлы.** Подписчик шины событий ставит задачу
  `materials:reclassify` при создании/изменении/восстановлении предмета и при разборе с новым синонимом
  (только если у группы подключён Диск). Задача заново классифицирует файлы Диска, ждущие во «Входящих»
  из-за низкой уверенности (ручные решения не трогает), и пишет в активность `drive.reclassified`
  («Файлы разобраны автоматически · N файлов»). Приложение перечитывает «Входящие» через 4 с.
- [x] **Индексируются файлы любых типов.** Решение D35: индексируем всё, в ленте — фильтр по типу
  файла (`file_type=DOCUMENT|IMAGE|AUDIO|VIDEO|ARCHIVE|OTHER`, чипы под поиском), иконки аудио/видео.
- [x] **Синоним — длинное имя папки целиком.** После разбора во «Входящих» — плашка «Папка «…» теперь
  синоним предмета» с кнопкой «Отменить» (ответ `classify` содержит `learned_alias`). В редакторе
  предмета синонимы — список с удалением каждого (раньше строка через запятую ломалась на именах папок
  с запятыми).
- [x] **Папки в индексе навсегда остаются в состоянии `NEW`.** Не требуется: `GET /drive/items` и
  статистика папки не показывают (видно было только в SQL напрямую).

- [x] **Публикация на Диск в «Мой диск» (D34).** Подключение аккаунта Google старосты через OAuth
  (`POST/DELETE /groups/{id}/drive/publisher`, возврат Google — `GET /drive/oauth/callback` с HTML-страницей
  результата), scope `drive` (D36). Refresh-токен — в `drive_publishers` под AES-GCM (`APP_ENCRYPTION_KEY`,
  привязан к группе). Публикация идёт от подключённого аккаунта, иначе сервисным аккаунтом и только в общем
  диске; загрузка «на Диск» без возможности опубликовать отклоняется сразу (`drive_publisher_required`).
  Отозванный Google доступ помечается и останавливает публикацию с подсказкой. Экран «Диск» — блок «Публикация
  загрузок на Диск». Интеграционный тест полного сценария (фейковый Google). Настройка консоли —
  `docs/GOOGLE-DRIVE.md`. Проверено вживую 2026-09-18: владелец папки подключился из браузера на компьютере,
  загрузка с телефона опубликована в «Мой диск». Аккаунт без прав редактора (доступ «все по ссылке —
  читатель») отклоняется, как задумано.
- [x] **Старые версии файла с Диска открывают текущее содержимое.** Версия хранит ревизию Диска
  (`material_versions.drive_revision_id`, миграция 00004, из `headRevisionId`); старые версии отдаются
  через `revisions.get` с Range, ссылка «Открыть в Google Диске» у них скрыта. Версии, проиндексированные
  раньше, находятся по md5 среди ревизий при первом открытии (id запоминается). Если Google ревизию уже
  удалил — 410 с кодом `version_unavailable`. Проверено на реальном файле «Лекция 2.pdf» (версия 1 отдаётся
  из ревизии, md5 совпал) и в интеграционном тесте (фейковый Диск с ревизиями). Полное решение — копия в S3
  (этап 5).
- [x] **Список материалов обновляется с задержкой после синхронизации.** `useGroupChanges` (core)
  раз в минуту, пока приложение открыто, читает журнал группы (`/sync?since=`) и помечает данные группы
  устаревшими, если появились события (в т.ч. от воркера Диска); на 410 — полное обновление. На телефоне
  `focusManager` подключён к `AppState`: при возврате в приложение устаревшее перечитывается. Тесты
  `pollGroupChanges`.
- [x] **Аудио/видео скачиваются вместо воспроизведения.** Встроенный плеер на экране материала
  (`components/media-player.tsx`): аудио — expo-audio (своя панель: пауза, ±15 с, перемотка касанием по
  полосе), видео — expo-video с системными элементами и полноэкранным режимом. Играет по `download_url`
  (S3) или `stream_url` (Диск через API, Range); ссылка обновляется за минуту до истечения, позиция
  сохраняется. Старые версии тоже проигрываются. Сервер отдаёт `audio/*`, `video/*`, `text/plain` как
  `inline`. Разрешение на микрофон отключено в плагине expo-audio. Проверить на телефоне (flac, mp4).
- [x] **Плеер остаётся на экране другого материала.** После прослушивания аудио плеер показывался при
  открытии картинки: `material/[id]` — скрытая вкладка, она не размонтируется, меняется только `id`, а
  состояние экрана (плеер, форма правки) сохранялось. Теперь содержимое пересоздаётся на каждый материал
  (`key={id}`), а уход с экрана останавливает воспроизведение.
- [x] **Не загружается видео с телефона.** Сервер пропускает загрузки только по списку расширений
  `UPLOAD_ALLOWED_EXT`, а аудио и видео в нём не было. Добавлены mp3, m4a, ogg, flac, wav, mp4, mov, webm,
  mkv с проверкой сигнатур (ID3/MPEG, ISO BMFF, OggS, fLaC, RIFF/WAVE, EBML) и MIME для плеера. Лимит
  размера оставлен 200 МБ (решение 2026-09-18): длинные записи — через Google Диск.
- [x] **Кириллица искажается на телефоне.** В ленте и в карточке материала названия, предметы и
  прочие данные превращались в «ÐÑÐ¸…». Причина — обёртка ответа при повторе после 401
  (`asResponse` в `packages/api-client`): тело передавалось как `ArrayBuffer`, а полифил `Response`
  в React Native (whatwg-fetch) декодирует его побайтно (Latin-1). Проявлялось после первого
  обновления access-токена, искажённые данные сохранялись в кеш. Теперь тело передаётся текстом,
  тест воспроизводит поведение полифила; сохранённый кеш сбрасывается (`QUERY_CACHE_BUSTER`).
- [x] **Нажатие срабатывает не с первого раза (телефон).** Пока открыта клавиатура, первое касание
  вложенного списка только закрывало её: `keyboardShouldPersistTaps="handled"` был лишь у `Screen`,
  а вложенные горизонтальные списки (чипы, выбор предмета/типа) и `FlatList` ленты его не наследуют.
  Добавлен везде; лента закрывает клавиатуру при прокрутке. Проверить на телефоне; если останется —
  смотреть задержку нажатий `ListRow` на Android.
- [x] **Неверная ошибка при выключенном Drive API.** `mapErr` распознаёт `accessNotConfigured` /
  `SERVICE_DISABLED` → 503 с кодом `drive_api_disabled` (сообщение Google со ссылкой — в тексте ошибки и
  `last_error`); 401 → `drive_auth_failed`. При старте `api`/`worker` — `about.get` и строка в логе
  (`google drive ready` или предупреждение). Диагностика дописана в `docs/GOOGLE-DRIVE.md`. Тест `TestMapErr`.
- [x] **Тексты ошибок Диска в приложении.** Машинные коды ошибок: RFC 7807 `type` =
  `urn:heatseeker:error:<code>` (`folder_link`, `folder_not_shared`, `not_a_folder`, `folder_trashed`,
  `drive_not_configured`, `drive_api_disabled`, `drive_auth_failed`; список — `ERROR_CODES` в shared).
  `describeError` переводит их (`errors.codes.*`, тест покрытия переводов), на экране Диска — кнопка
  «Скопировать» у адреса сервисного аккаунта. Ошибка синхронизации хранит и код (`last_error_code`,
  миграция 00006): экран «Диск» показывает перевод, текст Google — только если кода нет.

- [x] **Офисные файлы (pptx/docx/xlsx) по «Смотреть» скачиваются.** PDF-превью через Gotenberg (D37):
  сервис `gotenberg` в compose (:3030), `OFFICE_PREVIEW_URL`; задача `materials:preview` конвертирует и
  кладёт PDF в хранилище, `POST /materials/{id}/preview` запрашивает (для файлов с Диска — по первому
  «Смотреть»), `/open` отдаёт `preview_url`. В приложении «Смотреть» → «Готовлю просмотр…» → PDF; без
  превью — скачивание с пояснением. Проверено: docx с кириллицей через настоящий Gotenberg, сценарий в
  интеграционном тесте (фейковый конвертер). Открытие копии на Диске через «Смотреть» откатили — для этого
  есть «Открыть в Google Диске».
- [ ] **Подключение аккаунта Google с телефона в dev падает на localhost.** Google не принимает адрес
  локальной сети как адрес возврата, поэтому в dev подключать можно только из браузера на компьютере.
  На сервере с доменом (HTTPS) проблемы нет. Если понадобится в dev — туннель с HTTPS-адресом
  (`GDRIVE_OAUTH_REDIRECT_URL`).
- [ ] **Приложение Google в статусе Testing.** Подключение аккаунта живёт 7 дней; для постоянной работы —
  «Google Auth Platform → Audience → Publish app» (инструкция — в README, «Один раз»). Отметить, когда

## Разработка

- [x] **Телефон (Expo Go) не может зайти.** Если `EXPO_PUBLIC_API_URL` не задан, в dev адрес API
  выводится из хоста Metro (`Constants.expoConfig.hostUri`, тот же IP, что в `exp://…:4173`), в вебе —
  из `location.hostname`, порт 8000 (`apps/mobile/src/lib/api.ts`). Переменная остаётся главной.
- [x] **CORS для веба, открытого по IP.** В dev, кроме `CORS_ORIGINS`, разрешены `localhost`,
  loopback и адреса локальных сетей (`192.168.*`, `10.*`, `172.16–31.*`, IPv6 ULA) на любом порту
  (`AllowOriginFunc`, `transport/http/cors.go`, тест `TestAllowOrigin`). В проде — только `CORS_ORIGINS`.
- [x] **Подтверждения (`Alert.alert`) не работают в вебе.** Общий `confirm()` в `packages/ui`
  (native — Alert, веб — `window.confirm`); заменён в «Диске» и карточке материала.
- [x] **Адрес API и ошибка сети не видны в приложении.** В dev внизу первого экрана — «API (dev): <адрес>»;
  сетевая ошибка — «Сервер недоступен: <адрес>» (`describeError`).
- [x] **Предупреждение `Received true for a non-boolean attribute selectable` в вебе.** `selectable` →
  `userSelect="text"` (на native Tamagui сам ставит `selectable`).
- [x] **`GET /quick-tags` → `net::ERR_FAILED` в вебе.** Не повторялось; в логе API у `quick-tags` только
  200 и два 401 (истёкший access-токен, клиент обновлял и повторял). `ERR_FAILED` в браузере — обрыв
  соединения, вероятно, перезапуск API во время теста. Токен теперь обновляется заранее.
- [x] **Ошибка рендера `Chip` в вебе.** Это было то же предупреждение про `accessibilityRole`/
  `accessibilityState` (см. выше).
- [x] **Файлы на телефоне в dev.** Ссылки собирались с `localhost`: S3 — из `S3_PUBLIC_ENDPOINT`,
  файлы Диска (через API) — из `APP_BASE_URL` (по умолчанию `localhost:8000`). MinIO теперь можно
  открыть в сеть (`MINIO_BIND` в `infra/compose/.env`), настройка для телефона описана в README.
  Адреса из IP прописывает `task dev:ip` (после смены сети).

- [x] **Интеграционные тесты пишут в dev-базу.** Тесты по умолчанию работают с `heatseeker_test`
  (создаётся `infra/compose/postgres-init/`, на существующем томе — `createdb`), `TEST_DATABASE_URL` —
  в `.env.example`. Из dev-БД удалены 11 тестовых групп и 44 пользователя без групп (в т.ч. дубли
  регистрации с телефона).

## Этап 2: задачи и обсуждения (проверка 2026-09-21)

- [x] **Другой аккаунт на том же телефоне ловит 403 везде.** Выбранная группа запоминается на
  устройстве и переживает выход; новый аккаунт в ней не состоит. `useCurrentGroupGuard` (core)
  сбрасывает группу, если свежий список «мои группы» её не содержит (или членство не активно), —
  открывается выбор группы. Сама группа при выходе не забывается: тот же человек после входа
  попадает в неё сразу.
- [x] **Нельзя сменить группу из «Ещё».** Первая строка раздела «Группа» — текущая группа →
  экран «Мои группы / найти / создать».
- [x] **Удалённое сообщение не вернуть.** Автор видит у своего удалённого сообщения «Восстановить»
  (`POST /messages/:id/restore`, событие `message.undeleted`).
- [x] **Срок задачи вводится текстом.** Календарь месяца (с понедельника), «Сегодня / Завтра /
  Через неделю / Без срока» и необязательное время (быстрые варианты или «ЧЧ:ММ»). Срок без
  времени — конец дня (D42).
- [x] **Непонятно, где файлы задачи.** В карточке задачи раздел «Файлы»: список прикреплённых
  (открываются на экране материала по нажатию, заранее не грузятся), «Прикрепить из материалов»
  (поиск, сначала по предмету задачи) и «Загрузить файл» (загрузка сразу прикрепляется к задаче).
  Прикреплять может тот, кто правит задачу. `PUT /tasks/:id/materials`; правка задачи без
  `material_ids` больше не стирает вложения.
- [x] **Вторая новая задача подряд возвращала первую.** Экран «Новая задача» не размонтируется и
