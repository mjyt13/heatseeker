# ADR-0002: Бэкенд на Go

Дата: 2026-09-15 · Статус: принято

## Контекст

Нужна высокая скорость обработки при неизвестных ресурсах сервера, простой деплой и
предсказуемое потребление памяти. Специфика приложения (учебная группа, файлы, уведомления,
обсуждения) не накладывает ограничений на язык. Команда знакома с TypeScript, Java, Python;
Go — новый язык, выбран осознанно.

## Решение

- Go 1.23+, один статический бинарник `heatseeker` с подкомандами `api | worker | migrate | gen`.
- HTTP: `net/http` + chi + **huma v2** (code-first OpenAPI 3.1: Go-структуры → валидация,
  спека, `/docs`).
- Данные: PostgreSQL + pgx/v5 + **sqlc** (типобезопасный явный SQL) + goose (миграции).
- Фон: Redis + asynq (см. ADR-0006).
- Раскладка: `cmd/`, `internal/{domain,app,authz,transport,jobs,adapters,events,platform}` —
  зависимости направлены внутрь; интерфейсы — в `domain`, реализации — в `adapters`.
- Паттерны — в точках расширения: Strategy (хранилища, экстракторы, классификатор, каналы),
  Observer (журнал событий), Repository, Adapter (push), Command (задачи), Decorator (кеш
  медиа). Без generic-репозиториев и слоёв ради слоёв.

## Альтернативы

- **Node.js / NestJS (TypeScript).** Общие типы с клиентами «бесплатно», знакомый стек. Отклонено:
  приоритет — скорость обработки и низкое потребление ресурсов; типы всё равно генерируются из
  OpenAPI.
- **Python / FastAPI.** Лучшая экосистема ИИ, но медленнее и тяжелее по памяти для ядра; ИИ
  вынесен в отдельный сервис, где Python уместен.
- **gin / fiber / echo.** Нет преимуществ перед chi + huma для OpenAPI-first.
- **GORM / ent.** Скрывают SQL, GORM медленнее; ent остаётся запасным вариантом, если sqlc
  окажется слишком многословным.
- **oapi-codegen (spec-first).** Строже контракт, но больше ручной работы; переход возможен
  позже — спека уже будет.

## Последствия

- Плюс: ~30–50 MB RAM, деплой одним файлом (docker или systemd), высокая пропускная способность
  прокси-стриминга файлов и WebSocket.
- Минус: освоение Go — этап 0 длиннее; экосистема офисных форматов слабее — извлечение текста
  через CLI (poppler, LibreOffice) и zip+XML.
- Клиенты получают типы из OpenAPI (`openapi-typescript`), а не из общего кода.
