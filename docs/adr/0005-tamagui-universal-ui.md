# ADR-0005: Tamagui как единый UI-слой mobile + web

Дата: 2026-09-15 · Статус: принято (с планом отката)

## Контекст

Mobile-first на Expo, веб — вторым этапом на Vite + React. Требования к UI-киту: лёгкий, самый
быстрый по производительности, единый код для mobile и веба (или полноценный веб-аналог).
Отвергнуты заранее: MUI (медленный, ломкий), Ant Design (не подходит по стилю и весу).

## Решение

`packages/ui` на **Tamagui**: одни компоненты используются в `apps/mobile` (Expo) и `apps/web`
(через `@tamagui/vite-plugin`). Оптимизирующий компилятор извлекает стили в CSS на вебе и в
плоские `View` на native — без runtime-стилизации.

Страховка: на этапе 0 настройка Tamagui в монорепо (Expo + Vite + pnpm hoisted) ограничена
**2 днями**. Если стабильной сборки нет — откат на NativeWind + `react-native-reusables`
(mobile) и shadcn/ui (web) с общими Tailwind-токенами; факт отката фиксируется дополнением к
этому ADR.

## Альтернативы

- **NativeWind + react-native-reusables (mobile) + react-native-web.** Единый код, но на
  десктопе даёт «мобильный» UX для таблиц/досок; в Vite требует отдельной настройки RN-web.
- **NativeWind (mobile) + shadcn/ui (web) — «аналог».** Лучший нативный DOM на вебе, но
  компоненты пишутся дважды; общие только токены. Выбран как фолбэк.
- **React Native Paper / Gluestack.** Material-вид, тяжелее, слабее на вебе.

## Последствия

- Плюс: один набор компонентов, лучшая производительность рендера, темизация из коробки.
- Минус: более сложная конфигурация; версии Expo и Tamagui/Vite-плагина иногда расходятся —
  обновлять осторожно, фиксировать версии.
