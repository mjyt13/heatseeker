# ADR-0004: Лёгкая аутентификация в три уровня

Дата: 2026-09-15 · Статус: принято

## Контекст

Приложение для группы ~20 человек. Главное — быстрый доступ: любой одногруппник должен с первого
входа видеть материалы и писать в обсуждениях без email, паролей и OAuth-экранов. При этом
чувствительные действия (администрирование, модерация, загрузка на Google Диск) требуют
надёжной идентификации, а в будущем вступление в группу должно уметь быть закрытым.

## Решение

| Уровень | Как | Даёт |
|---|---|---|
| **L1** (по умолчанию) | регистрация только по имени; сессия привязана к устройству (refresh-токен с ротацией в secure store, access JWT 15 мин) | чтение всего, обсуждения, задачи, напоминания, загрузка в наше хранилище, закладки |
| **L2** | пользователь добавляет пароль и/или email и/или Google («Защитить аккаунт») | вход с других устройств, восстановление; **обязателен** для ролей ADMIN / MODERATOR / HEADMAN (`AUTH_REQUIRE_SECURED_FOR`) |
| **L2g** | Google Sign-In с Drive-scope | загрузка на Google Диск от своего имени |
| **L0** | `groups.public_read=true` | чтение без аккаунта по ссылке; **выключен по умолчанию**, оставлен переключателем |

Email опционален и уникален, если задан. Вступление: `join_policy = OPEN | INVITE | APPROVAL`
(MVP — OPEN по ссылке/коду; модель и эндпоинты готовы к закрытой схеме). Роли на членстве —
массив (мультироли).

## Альтернативы

- **Классическая регистрация email + пароль.** Лишнее трение для аудитории, email нужен единицам.
- **Managed auth (Supabase / Keycloak / Clerk).** Логика инвайтов и per-group ролей всё равно
  наша; внешняя зависимость и лишний контейнер.
- **Только Google Sign-In.** Не все хотят подключать Google ради чтения; нужен только для
  загрузки на Диск.

## Последствия

- Плюс: вход за 5 секунд; усиление аккаунта — по необходимости.
- Минус: L1-аккаунт без credentials невосстановим при потере устройства (UI предупреждает при
  первом входе и при назначении роли); нужна аккуратная защита от массовых регистраций
  (rate limit, код группы).
