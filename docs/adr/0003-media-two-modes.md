# ADR-0003: Три режима работы с медиа — LINK / CACHE / IMPORT

Дата: 2026-09-15 · Статус: принято

## Контекст

Материалы группы лежат на чужом Google Диске и бывают тяжёлыми (лекции, презентации, записи).
Серверные мощности и диск не гарантированы: может не быть места под копии файлов. При этом
желаемый вариант — собственное S3-хранилище (MinIO) для быстрого доступа, превью, поиска по
содержимому и обработки ИИ.

## Решение

Интерфейс `MediaStore` с реализациями `s3`, `local`, `drive` и режим на уровне группы
(`groups.media_mode`, дефолт `MEDIA_MODE_DEFAULT`):

| Режим | Файл | Просмотр |
|---|---|---|
| **LINK** | остаётся на Диске; у нас — метаданные | ссылка `web_view_link` (Google) или прокси-стрим через сервисный аккаунт с `Range` (`MEDIA_PROXY_ENABLED`) |
| **CACHE** | Диск — источник; копия в S3 с TTL (`MEDIA_CACHE_TTL_HOURS`, продлевается при обращении), лимит `MEDIA_CACHE_MAX_GB`, вытеснение LRU; небольшие файлы кешируются заранее | presigned GET из S3, при промахе — как LINK |
| **IMPORT** | постоянная копия в S3 | presigned GET |

Режим CACHE реализован как Decorator над `MediaStore`; переключение режимов — без правок кода.
TTL и лимиты вынесены в env с расчётом, что кеш позже станет постоянным хранилищем. Загрузка из
приложения всегда идёт в наше хранилище (S3 или `local`), опционально — на Диск.

## Альтернативы

- **Только ссылки на Диск.** Нет превью, поиска по содержимому, обработки ИИ, зависимость от
  доступности Google и от прав студентов на папку.
- **Только импорт в S3.** Требует диска под весь объём, которого может не быть.
- **Двусторонняя синхронизация с Диском.** Сложно, конфликтует с нативной работой одногруппников
  в Drive; отклонено для MVP.

## Последствия

- Плюс: работает на сервере без диска (LINK) и масштабируется до полноценного хранилища
  (IMPORT) одной настройкой.
- Минус: три пути отдачи файла в клиенте (`GET /materials/:id/open` возвращает `mode` и нужные
  ссылки); файлы в LINK не проходят антивирус (лежат у Google — UI это показывает).
