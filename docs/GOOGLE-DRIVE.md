# Google Диск: настройка сервисного аккаунта

Ядро работает с Диском от имени сервисного аккаунта (D7, D29): индексирует папку группы,
отдаёт файлы через сервер и (при `FEATURE_DRIVE_UPLOAD=true`) публикует загрузки в папку (D32).
Студентам ничего настраивать не нужно.

## 1. Создать сервисный аккаунт и ключ (один раз на сервер)

1. Открыть <https://console.cloud.google.com/>, создать проект (например, `heatseeker`).
2. «APIs & Services» → «Library» → найти **Google Drive API** → «Enable».
3. «IAM & Admin» → «Service Accounts» → «Create service account». Имя — любое
   (`heatseeker-drive`). Роли проекта не нужны — шаги 2 и 3 мастера можно пропустить.
4. Открыть созданный аккаунт → вкладка «Keys» → «Add key» → «Create new key» → **JSON**.
   Скачается файл вида `heatseeker-xxxx.json` — это секрет, в репозиторий его не класть.
   Если в организации включена политика `iam.disableServiceAccountKeyCreation`, создать ключ
   не получится — нужен личный Google-аккаунт или разрешение администратора.
5. Запомнить адрес аккаунта — поле `client_email`
   (`heatseeker-drive@<проект>.iam.gserviceaccount.com`).

## 2. Передать ключ ядру

```bash
base64 -w0 heatseeker-xxxx.json   # macOS: base64 -i heatseeker-xxxx.json
```

Результат — одной строкой в `apps/api/.env`:

```
GDRIVE_SERVICE_ACCOUNT_JSON_BASE64=eyJ0eXBlIjoic2VydmljZV9hY2NvdW50Ii...
FEATURE_DRIVE_UPLOAD=true      # если нужна публикация загрузок на Диск
```

После перезапуска `heatseeker api` и `heatseeker worker` экран «Ещё → Google Диск» покажет
адрес сервисного аккаунта.

## 3. Открыть папку группы для сервисного аккаунта

1. В Google Диске: папка группы → «Поделиться» → добавить `client_email` из шага 1.5.
   - **Редактор** — индексация и публикация из приложения;
   - **Читатель** — только индексация (публикация будет недоступна, приложение это покажет).
2. Скопировать ссылку на папку.
3. В приложении (староста или админ с защищённым аккаунтом): «Ещё → Google Диск» → вставить
   ссылку → «Подключить». Первая индексация стартует сразу, дальше — каждые
   `GDRIVE_SYNC_INTERVAL_SEC` (10 мин), полный перескан — раз в сутки.

Для проверки хватит тестовой папки с несколькими файлами, разложенными по подпапкам-предметам
(`Матан/Лекции/Tema1_Lektsia1.pdf` и т.п.).

## Ограничение: публикация работает только в общем диске

У сервисных аккаунтов **нет собственной квоты хранения**, и они не могут владеть файлами в
«Моём диске» пользователя: загрузка в обычную папку завершится ошибкой `storageQuotaExceeded`
([документация Google](https://developers.google.com/workspace/drive/api/guides/about-shareddrives)).
Поэтому:

| Где лежит папка группы | Индексация и просмотр | Публикация из приложения |
|---|---|---|
| «Мой диск» владельца (обычный Gmail) | работает | не работает — приложение покажет «Не удалось опубликовать на Диске» с подсказкой |
| Общий диск (Shared Drive, нужен Google Workspace) | работает | работает, файлы расходуют квоту организации |

Для обычного Gmail решено (D34) публиковать от имени подключённого через OAuth аккаунта старосты — в его квоте; сервисный аккаунт остаётся для индексации. Пока это не реализовано, публикация в «Мой диск» падает с ошибкой квоты (проверено вживую), файл остаётся в хранилище приложения.

## Диагностика

- `GET /api/v1/groups/{groupId}/drive/status` — состояние, последняя ошибка, счётчики.
- `GET /api/v1/groups/{groupId}/drive/items?state=SKIPPED|ERROR|DELETED` — что с каждым файлом.
- asynqmon (<http://localhost:8082>) — очереди `drive:sync`, `drive:upload`.
- «Folder is not shared with …» при подключении — папка не открыта для `client_email`.
