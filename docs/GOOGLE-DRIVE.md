# Google Диск: настройка сервисного аккаунта

Ядро работает с Диском от имени сервисного аккаунта (D7, D29): индексирует папку группы,
отдаёт файлы через сервер и (при `FEATURE_DRIVE_UPLOAD=true`) публикует загрузки в папку (D32).
Студентам ничего настраивать не нужно.

## 1. Создать сервисный аккаунт и ключ (один раз на сервер)

1. Открыть <https://console.cloud.google.com/>, создать проект (например, `heatseeker`).
2. «APIs & Services» → «Library» → найти **Google Drive API** → «Enable».
3. «IAM & Admin» → «Service Accounts» → «Create service account». Имя — любое
   (`heatseeker-drive`). Роли проекта не нужны — шаги 2 и 3 мастера можно пропустить.
4. Открыть созданный аккаунт → вкладка «Keys» → «Add key» → «Create new key» → **JSON**.
   Скачается файл вида `heatseeker-xxxx.json` — это секрет, в репозиторий его не класть.
   Если в организации включена политика `iam.disableServiceAccountKeyCreation`, создать ключ
   не получится — нужен личный Google-аккаунт или разрешение администратора.
5. Запомнить адрес аккаунта — поле `client_email`
   (`heatseeker-drive@<проект>.iam.gserviceaccount.com`).

## 2. Передать ключ ядру

```bash
base64 -w0 heatseeker-xxxx.json   # macOS: base64 -i heatseeker-xxxx.json
```

Результат — одной строкой в `apps/api/.env`:

```
GDRIVE_SERVICE_ACCOUNT_JSON_BASE64=eyJ0eXBlIjoic2VydmljZV9hY2NvdW50Ii...
FEATURE_DRIVE_UPLOAD=true      # если нужна публикация загрузок на Диск
```

После перезапуска `heatseeker api` и `heatseeker worker` экран «Ещё → Google Диск» покажет
адрес сервисного аккаунта.

## 3. Открыть папку группы для сервисного аккаунта

1. В Google Диске: папка группы → «Поделиться» → добавить `client_email` из шага 1.5.
   - **Редактор** — индексация и публикация из приложения;
   - **Читатель** — только индексация (публикация будет недоступна, приложение это покажет).
2. Скопировать ссылку на папку.
3. В приложении (староста или админ с защищённым аккаунтом): «Ещё → Google Диск» → вставить
   ссылку → «Подключить». Первая индексация стартует сразу, дальше — каждые
   `GDRIVE_SYNC_INTERVAL_SEC` (10 мин), полный перескан — раз в сутки.

Для проверки хватит тестовой папки с несколькими файлами, разложенными по подпапкам-предметам
(`Матан/Лекции/Tema1_Lektsia1.pdf` и т.п.).

## Публикация загрузок на Диск

У сервисных аккаунтов **нет собственной квоты хранения**, и они не могут владеть файлами в
«Моём диске» пользователя: загрузка в обычную папку завершится ошибкой `storageQuotaExceeded`
([документация Google](https://developers.google.com/workspace/drive/api/guides/about-shareddrives)).
Поэтому:

| Где лежит папка группы | Индексация и просмотр | Публикация из приложения |
|---|---|---|
| «Мой диск» владельца (обычный Gmail) | работает | от имени подключённого аккаунта Google (D34), в его квоте |
| Общий диск (Shared Drive, нужен Google Workspace) | работает | сервисным аккаунтом (квота организации) или от подключённого аккаунта |

Сервисный аккаунт остаётся для индексации; аккаунт Google нужен только для загрузки. Пока он не
подключён, приложение не предлагает «Опубликовать на Диске» для папки в «Моём диске».

### Настройка OAuth-клиента (один раз на сервер)

В том же проекте Google Cloud, где сервисный аккаунт:

1. **Google Auth Platform → Branding:** название приложения, почта поддержки.
2. **Audience:** тип **External**; в **Test users** — аккаунт, который будет публиковать.
3. **Data access → Add or remove scopes:** `https://www.googleapis.com/auth/drive` (полный доступ:
   `drive.file` не позволяет создавать файлы в папке, которую приложение не создавало).
4. **Clients → Create client → Web application**, в **Authorized redirect URIs** — адрес возврата:
   - dev: `http://localhost:8000/api/v1/drive/oauth/callback` (Google не принимает IP локальной сети,
     поэтому в dev подключать аккаунт нужно из браузера на компьютере — веб-версия приложения);
   - прод: `https://<домен>/api/v1/drive/oauth/callback` (или `GDRIVE_OAUTH_REDIRECT_URL`).
   Точный адрес API пишет в лог при старте: `google drive publishing account can be connected redirect_url=…`.
5. Client ID и Client secret — в `apps/api/.env` (`GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`);
   нужен и `APP_ENCRYPTION_KEY` (≥ 32 символов): им шифруется refresh-токен аккаунта. Не коммитить.
6. Пока приложение в статусе **Testing**, Google выдаёт refresh-токен на 7 дней — после этого аккаунт
   придётся подключать заново. Для постоянной работы — **Audience → Publish app** (без проверки Google,
   до 100 пользователей; при входе будет предупреждение «приложение не проверено» → «Дополнительно →
   Перейти»).

### Подключение аккаунта в приложении

«Ещё → Google Диск → Публикация загрузок на Диск → Подключить аккаунт Google» (староста/админ с
защищённым аккаунтом). Войти аккаунтом-владельцем папки (или с правами редактора) и отметить доступ
к Google Диску. Сервер проверяет, что аккаунт может добавлять файлы в папку группы, и хранит
refresh-токен зашифрованным (`drive_publishers`). «Отключить» удаляет токен и отзывает его у Google.
Если Google отозвал доступ (сменили пароль, убрали доступ в настройках аккаунта), публикация
останавливается с подсказкой «подключите заново».

## Старые версии файлов

Когда файл на Диске заменяют новым содержимым, в приложении появляется новая версия, а старые
открываются из ревизий Google (`revisions.get`). Google хранит ревизии обычных файлов около 30 дней
(или 100 последних), если в «Управлении версиями» не отмечено «Не удалять». Когда ревизии уже нет,
приложение пишет «Эта версия больше недоступна». Для Google Документов версии не ведутся — открывается
текущий документ. Надёжное хранение старых версий — копия в S3 (режимы CACHE/IMPORT, этап 5).

## Диагностика

- `GET /api/v1/groups/{groupId}/drive/status` — состояние, последняя ошибка, счётчики.
- `GET /api/v1/groups/{groupId}/drive/items?state=SKIPPED|ERROR|DELETED` — что с каждым файлом.
- asynqmon (<http://localhost:8082>) — очереди `drive:sync`, `drive:upload`.
- При старте `api` и `worker` пишут в лог `google drive ready` — ключ рабочий и API включён. Иначе —
  предупреждение: `google drive API is disabled` (включить **Google Drive API** в проекте ключа:
  «APIs & Services» → «Library»; изменение доходит за несколько минут) или `google drive check failed`
  (ключ отозван, нет сети).
- «Папка не найдена или не открыта для …» при подключении — папка не открыта для `client_email`
  (или ссылка ведёт на чужую/удалённую папку).
- «В облачном проекте сервера не включён Google Drive API» — см. первый пункт; доступ к папке тут ни
  при чём.
