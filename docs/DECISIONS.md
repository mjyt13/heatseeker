# Heatseeker — лог решений

Решения, принятые при планировании (2026-09-15). Изменение решения — новая строка со ссылкой на
отменяемую, а не правка старой. Крупные архитектурные решения дополнительно оформлены в
[`adr/`](adr/).

| D31 | В сообщениях коммитов нет строк авторства ИИ-агента (`Co-Authored-By`, `Claude-Session`); исключение — первый коммит | пожелание автора |
| D32 | Загрузка на Google Диск из приложения входит в MVP — способ A (через сервисный аккаунт, `FEATURE_DRIVE_UPLOAD`); закрывает открытый вопрос №1 (2026-09-16). Публиковать может любой участник, кроме GUEST, с защищённым аккаунтом (`drive.upload`, как в `AUTH_REQUIRE_SECURED_FOR`) | решение автора; файл на Диске подписан «Загрузил: <имя>» |
| D33 | Вступление в группу — поиском по названию и сразу, без заявки (группы видны в поиске все); код/ссылка — дополнительный путь внизу экрана | приложение пока для одной группы, аудитория узкая; `join_policy` позволит закрыть доступ позже (2026-09-17) |
| D34 | Публикация на Диск в «Мой диск» обычного Gmail — через OAuth одного «публикующего» Google-аккаунта (староста): refresh-токен в БД (AES-GCM, `APP_ENCRYPTION_KEY`), файлы в его квоте; сервисный аккаунт остаётся для индексации. В перспективе — несколько подключений Диска на группу (разные аккаунты/папки) | Workspace-диска нет; рабочий диск группы — личный аккаунт с большим тарифом (закрывает открытый вопрос №6, 2026-09-17) |
| D35 | С Диска индексируются файлы любых типов (аудио, картинки, архивы); allowlist расширений действует только для загрузок из приложения. В ленте — фильтр по типу файла | на Диске группы лежат и записи лекций, и сканы; решать, что показывать, удобнее фильтром, чем правилами индексации (2026-09-17) |
| D36 | Аккаунт публикации (D34) запрашивает полный доступ `drive` (не `drive.file`: он не даёт создавать файлы в существующей папке группы). Выбор, кем публиковать, — автоматический: подключённый аккаунт, иначе сервисный аккаунт и только в Shared Drive; переменная `DRIVE_UPLOAD_MODE` убрана | 2026-09-18 |
| D37 | Офисные файлы (pptx/docx/xlsx/odt/rtf…) показываются через PDF-превью: воркер конвертирует их через Gotenberg (LibreOffice) и кладёт PDF в хранилище приложения (`groups/{g}/previews/{version}.pdf`), в том числе для файлов с Диска в режиме LINK. Загрузки конвертируются сразу, файлы с Диска — по первому «Смотреть». Без превью (выключено, больше `OFFICE_PREVIEW_MAX_MB`, ошибка) файл скачивается. Перенесено из этапа 5 | браузер и телефон не показывают офисные форматы; открывать копию на Диске через «Смотреть» отклонено — для этого есть отдельная кнопка (2026-09-19) |
| D38 | Дедлайны задач: сканер раз в минуту объявляет приближение срока событием группы (`task.due_soon`, `task.overdue`) — по офсетам `DEADLINE_REMINDER_OFFSETS` (по умолчанию 7d, 3d, 1d, 3h и сам срок), один раз на офсет; уже объявленные офсеты хранятся в `tasks.notified_offsets`, перенос срока включает напоминания заново. Личные уведомления (push, преференции, mute, тихие часы) добавит блок уведомлений этого же этапа; кастомные напоминания (`reminders`) — вместе с ним | событиям уже есть куда идти (журнал группы → синк и лента активности), а доставке по каналам — ещё нет; так задачи работают сразу и без дублирования механизмов (2026-09-20) |
| D39 | Личный прогресс участника по задаче (`task_assignments.status`) не пишется в журнал группы, а общий статус — пишется | «я сделал» — не новость группы; события бы засоряли ленту активности (2026-09-20) |
| D40 | Обсуждения адресуются тем, о чём они (`SUBJECT`, `GENERAL`, `MATERIAL`, `TASK`; `LESSON` — с этапа 3, `PROPOSAL` — с этапа 4): тред создаётся первым сообщением, пустое обсуждение ничего не пишет. События `message.*` несут только id (тред, цель, автор, ответ), без текста; создание, правка и удаление не попадают в ленту активности, модерация (`message.hidden` / `message.restored`) — попадает. Скрытие для себя и отметка прочтения — личные, без событий (как D39). Текст скрытого модератором видят автор и модераторы; кто скрыл — только модераторы. Удалить можно только своё сообщение, в треде остаётся пометка | журнал группы append-only и хранится `EVENT_LOG_RETENTION_DAYS`: текст в нём пережил бы удаление и модерацию; клиенты и так перечитывают тред по событию; треды «про запас» для каждого предмета не нужны (2026-09-21) |
| D41 | Офлайн-outbox сообщений — очередь в `@heatseeker/core` (zustand) с подключаемым хранилищем; в mobile — AsyncStorage (`heatseeker.outbox`), а не expo-sqlite из таблицы стека. Отправка по порядку, повтор по тому же `client_id`; сеть/5xx/429 — ждать и повторять (каждые 15 с, пока очередь не пуста), прочий отказ сервера — пометить «не отправлено» и дать автору повторить или удалить. При выходе из аккаунта очередь очищается | очередь — несколько коротких текстов, SQL для неё не нужен, а AsyncStorage уже подключён для кеша запросов; хранилище спрятано за интерфейсом `OutboxStorage`, так что переход на expo-sqlite (вместе с локальной БД сообщений для офлайн-чтения) не затронет экраны (2026-09-21) |
| D42 | Срок задачи без времени — конец выбранного дня (23:59 по времени телефона), такой срок показывается одной датой; время указывается по желанию. Срок выбирается календарём (свой компонент на Tamagui), а не текстом и не нативным пикером | «сдать 25.12» значит «до конца 25-го», а 00:00 делало задачу просроченной с утра того же дня; нативный пикер разный на Android/iOS и отсутствует в вебе, свой календарь одинаков везде (2026-09-21) |
| D43 | Файл, загруженный из задачи, по умолчанию остаётся «только в задаче» (`materials.task_id`): его нет в ленте, поиске и «Входящих», он не публикуется на Диск и не обсуждается отдельно; видят его те, кто видит задачу (для личной задачи — только автор), загрузивший и модераторы. Выбор — при загрузке («Только в задаче» / «В материалы группы»); позже файл можно «Открыть группе» (`POST /materials/:id/share`: загрузивший, тот, кто правит задачу, модератор) — он становится обычным материалом и остаётся прикреплённым. Такой файл нельзя прикрепить к другой задаче. Событие `material.added` для него не попадает в ленту активности; при открытии группе — попадает | автор задачи решает сам, делиться ли черновиком или решением; отдельная таблица «файлов задачи» дублировала бы хранение, превью и открытие файлов — материал уже умеет всё это (2026-09-21) |
| D44 | Группу выбирают уже на первом экране: имя, поиск по названию и список открытых групп (`GET /groups/discover` — без токена, те же открытые группы, что в поиске D33, без признаков членства), код приглашения — по ссылке «Есть код приглашения?». Регистрация принимает `group_id` открытой группы и сразу вступает в неё (код приглашения важнее). Закрытые (`INVITE`) группы не показываются и по `group_id` не вступают. Не выбрал — после входа экран групп (найти, создать, код) | вход должен сразу вести в свою группу, без лишнего шага; названия открытых групп и так видит любой, кто зарегистрировался по одному имени, так что их выдача до регистрации ничего не раскрывает; закрыть группу по-прежнему можно `join_policy` (2026-09-21) |
| D45 | Расписание: занятие — разовое или еженедельная серия (каждую неделю / через неделю — «числитель/знаменатель», до 4 недель; дни недели; последний день `until`). Хранится как подмножество RRULE (`FREQ=WEEKLY;INTERVAL;BYDAY`), занятия не хранятся, а разворачиваются при чтении в часовом поясе серии (IANA, берётся с телефона создателя), поэтому время по часам не сдвигается. Одно занятие отменяется или меняется (время, день, аудитория, преподаватель, причина) исключением по дню плана; отменённое остаётся в расписании зачёркнутым. «Изменить с этого дня» делит серию: старая заканчивается накануне, изменения отдельных занятий с этого дня переходят к новой. Правка и удаление серии — с версией (оптимистичная блокировка, 409). Правит староста/админ с защищённым аккаунтом (D22), события `schedule.*` — в журнал и ленту активности. Треды занятий (`LESSON`) и запросы на изменение — следующими шагами этапа 3; из занятия пока открывается обсуждение предмета | хранить развёрнутые занятия пришлось бы продлевать и переписывать при каждой правке серии; RRULE-подмножество напрямую ложится в ICS; отмену должны увидеть, а не потерять (2026-09-22) |
| D46 | Календарь телефона — подписка по личной ссылке на ICS (`GET /groups/:id/schedule.ics?token=`): токен подписан (как ссылки на файлы), работает год, членство проверяется при каждом запросе; отзыв ссылки — только сменой секрета. Серия — один VEVENT с RRULE, отмена — EXDATE, изменение — VEVENT с RECURRENCE-ID | календарные приложения не умеют заголовок авторизации; отдельная таблица токенов с отзывом — когда понадобится. Google Календарь забирает ссылку со своих серверов, поэтому работает только с публичным адресом API (в локальной сети — приложения вроде ICSx⁵) (2026-09-22) |
| D47 | У картинок (jpeg/png/gif/webp) есть уменьшенная копия: JPEG до 640 px, повёрнутая по EXIF, делается при первом запросе и хранится рядом с файлами (`groups/{g}/thumbs/{version}.jpg`), в том числе для файлов с Диска. Ссылка `thumbnail_url` в версии материала подписана на сутки; телефон кеширует картинку по id версии, поэтому в задаче и на экране материала превью видно сразу и без сети. Полный размер открывается во встроенном просмотрщике (тоже кешируется), браузер — запасной кнопкой. PDF и прочее пока открываются в браузере | фото доски или задания должно быть видно без нажатий; 50 КБ вместо нескольких МБ; очередь воркера для этого не нужна — уменьшение занимает доли секунды (2026-09-22) |
| D48 | Новые сообщения по умолчанию приходят участнику из обсуждений предметов его группы (все предметы, без подписки); отключается mute по теме на время. Общий чат и обсуждения материалов/задач — открытый вопрос №7. Сами уведомления ещё не сделаны: решение задаёт их поведение по умолчанию | обсуждения предметов — основное место разговора группы, их немного; закрывает открытый вопрос №4 (2026-09-22) |
